# クレームAI自動分類システム（食品スーパー・ディスカウントストア向け）

Googleスプレッドシートの **AI関数（`=AI()` / `=Gemini()`）** を使い、クレーム原文から
**大分類 → 中分類 → 小分類 → 発生場面 → 原因分類** を自動で候補出しし、
最終的に人が確定する運用を構築するための一式です。

そのままコピーして使える **数式・GASコード・マスター表** を同梱しています。

---

## 0. 列構成の相談への回答（重要）

ご相談いただいた2点に対応しました。

### (1) 列が変わっている件 → **A〜U を維持し、V〜Y を追加**
元仕様の A〜U 列はそのまま維持し、**小分類パイプラインを V〜Y に「追記」** する方式にしました。

| 変更 | 内容 | 理由 |
|---|---|---|
| 追加 V | 小分類候補文 | 大分類・中分類に一致する小分類だけを抽出 |
| 追加 W | 小分類用結合文 | AI小分類の入力（単一セル参照用） |
| 追加 X | AI小分類 | `=AI(W2)` |
| 追加 Y | 確定小分類 | 人が確定（プルダウン） |

**なぜ挿入ではなく末尾追加か**：A〜U の途中に列を挿入すると既存データ・数式の参照が全てズレて
移行事故のもとになります。末尾に足せば **既存の列・データを1つも壊さず** 小分類機能を追加できます。
処理の論理順序（大→中→小）は数式内の参照で担保しており、物理的な列の並びに依存しません。

**移行手順**：既存シートがある場合も、GASの「初期セットアップ」を実行するだけで V〜Y のヘッダと数式が
追加されます（A〜E の原文、N/O/T/U/Y の確定値には一切触れません）。

### (2) 小分類まで自動仕訳したい件 → **3階層（大・中・小）を実装**
「大中小分類は用意済み」とのことなので、**小分類マスター（`仕訳ルールマスター_小分類`）** を用意しました。
`src/Config.gs` の `MASTER_SHO`（＝ `masters/仕訳ルールマスター_小分類.csv`）を
**貴社の準備済み小分類で置き換える／追記するだけ** で、AIが大分類・中分類に紐づく小分類候補から自動選択します。

> 同梱の小分類はテストケースを通すためのサンプルです。列構成（大分類/中分類/小分類/定義/入る例/しない例）を
> 保ったまま、準備済みデータへ差し替えてください。

## 2. A〜Y列 一覧（クレーム記録）

| 列 | 項目 | 種別 | 内容 |

| A | 受付No | 入力 | 手入力 |

| G | 大分類用結合文 | 数式 | 候補＋ルール＋原文を結合 |
| H | AI大分類 | AI | `=AI(G2)` |
| I | 中分類候補文 | 数式 | H に一致する中分類のみ抽出 |
| J | 中分類用結合文 | 数式 | 候補＋ルール＋大分類＋原文 |
| K | AI中分類 | AI | `=AI(J2)` |
| L | 補助セル | 数式 | AI理由用の結合文 |
| M | AI理由 | AI | `=AI(L2)` |

| O | 確定中分類 | 確定 | プルダウン（人） |

| R | 原因分類候補文 | 数式 | 候補＋ルール＋大中＋場面＋原文 |
| S | AI原因分類 | AI | `=AI(R2)` |
| T | 確定発生場面 | 確定 | プルダウン（人） |
| U | 確定原因分類 | 確定 | プルダウン（人） |
| **V** | **小分類候補文** | 数式 | H×K に一致する小分類のみ抽出 |

- **結合文はすべて通常関数**（`TEXTJOIN`/`FILTER`/`ARRAYFORMULA`）で作り、AI関数の外側に置く。

## 3. 各列へ入れる完成数式（row2。下方向にコピー）

> `AI` の部分は環境により `Gemini` に置換（後述）。GASを使う場合は自動で全行に設定されます。

**F2（匿名化）**
```
=IF($E2="","",ANONYMIZE($E2))
```

**G2（大分類用結合文）**
```
=IF($F2="","","あなたは食品スーパー・ディスカウントストアのクレーム分類担当です。次のクレーム内容を読み、下記の大分類候補の中から最も適切なものを1つだけ選び、候補の表記どおりに分類名のみを出力してください。説明・記号・前置きは不要です。"&CHAR(10)&"【判定方針】お客様が最初に強く不満を持った主因で判定する。安易に接客・応対やその他へ寄せない。"&CHAR(10)&"【大分類候補と定義】"&CHAR(10)&TEXTJOIN(CHAR(10),TRUE,ARRAYFORMULA(IF('仕訳ルールマスター_大分類'!$A$2:$A$12="","","■"&'仕訳ルールマスター_大分類'!$A$2:$A$12&"｜定義:"&'仕訳ルールマスター_大分類'!$B$2:$B$12&"｜入る例:"&'仕訳ルールマスター_大分類'!$C$2:$C$12&"｜しない例:"&'仕訳ルールマスター_大分類'!$D$2:$D$12&"｜着眼点:"&'仕訳ルールマスター_大分類'!$E$2:$E$12)))&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】大分類名を1つだけ。")
```

**H2（AI大分類）**
```
=AI($G2)
```

**I2（中分類候補文）**
```
=IF($H2="","",TEXTJOIN(CHAR(10),TRUE,IFERROR(FILTER("■"&'仕訳ルールマスター_中分類'!$B$2:$B$400&"｜定義:"&'仕訳ルールマスター_中分類'!$C$2:$C$400&"｜入る例:"&'仕訳ルールマスター_中分類'!$D$2:$D$400&"｜しない例:"&'仕訳ルールマスター_中分類'!$E$2:$E$400,'仕訳ルールマスター_中分類'!$A$2:$A$400=$H2),"")))
```

**J2（中分類用結合文）**
```
=IF($I2="","","次のクレーム内容について、指定された大分類に属する中分類候補の中から最も適切なものを1つだけ選び、候補の表記どおりに中分類名のみを出力してください。説明は不要です。"&CHAR(10)&"【大分類】"&$H2&CHAR(10)&"【中分類候補】"&CHAR(10)&$I2&CHAR(10)&"【判定の注意】従業員個人の爪・髪・制服・名札・清潔感の問題は身だしなみ不備。商品の異物混入や店舗全体の衛生は身だしなみ不備に含めない。"&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】中分類名を1つだけ。")
```

**K2（AI中分類）**
```
=AI($J2)
```

**V2（小分類候補文：大分類×中分類でFILTER）**
```
=IF(OR($H2="",$K2=""),"",TEXTJOIN(CHAR(10),TRUE,IFERROR(FILTER("■"&'仕訳ルールマスター_小分類'!$C$2:$C$1500&"｜定義:"&'仕訳ルールマスター_小分類'!$D$2:$D$1500&"｜入る例:"&'仕訳ルールマスター_小分類'!$E$2:$E$1500,'仕訳ルールマスター_小分類'!$A$2:$A$1500=$H2,'仕訳ルールマスター_小分類'!$B$2:$B$1500=$K2),"")))
```

**W2（小分類用結合文）**
```
=IF($V2="","","次のクレーム内容について、指定された大分類・中分類に属する小分類候補の中から最も適切なものを1つだけ選び、候補の表記どおりに小分類名のみを出力してください。該当が無ければ最も近いものを選ぶ。説明は不要です。"&CHAR(10)&"【大分類】"&$H2&"／【中分類】"&$K2&CHAR(10)&"【小分類候補】"&CHAR(10)&$V2&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】小分類名を1つだけ。")
```

**X2（AI小分類）**
```
=AI($W2)
```

**L2（AI理由用結合文）**
```
=IF($F2="","","次のクレームが、なぜ下記の分類になるのかを40文字以内で簡潔に説明してください。分類名の列挙ではなく理由を述べる。"&CHAR(10)&"【大分類】"&$H2&"／【中分類】"&$K2&"／【小分類】"&$X2&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】40文字以内の理由文。")
```

**M2（AI理由）**
```
=AI($L2)
```

**P2（発生場面候補文）**
```
=IF($F2="","","次のクレームで、お客様の不満が最初に強くなった発生場面を、下記候補から1つだけ選び候補の表記どおりに場面名のみ出力してください。説明は不要です。"&CHAR(10)&"【発生場面候補】"&CHAR(10)&TEXTJOIN(CHAR(10),TRUE,ARRAYFORMULA(IF('発生場面マスター'!$A$2:$A$60="","","・"&'発生場面マスター'!$A$2:$A$60&IF('発生場面マスター'!$B$2:$B$60=""," "," : "&'発生場面マスター'!$B$2:$B$60))))&CHAR(10)&"【判定ルール】"&TEXTJOIN(" ",TRUE,'発生場面ルールマスター'!$A$2:$A$60)&CHAR(10)&"【参考】大分類:"&$H2&"／中分類:"&$K2&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】場面名を1つだけ。")
```

**Q2（AI発生場面）**
```
=AI($P2)
```

**R2（原因分類候補文）**
```
=IF($F2="","","次のクレームについて、顧客が訴えた表面的な不満ではなく社内として直すべき背景要因を、下記候補から1つだけ選び候補の表記どおりに原因名のみ出力してください。説明は不要です。"&CHAR(10)&"【原因分類候補】"&CHAR(10)&TEXTJOIN(CHAR(10),TRUE,ARRAYFORMULA(IF('原因分類マスター'!$A$2:$A$60="","","・"&'原因分類マスター'!$A$2:$A$60&IF('原因分類マスター'!$B$2:$B$60=""," "," : "&'原因分類マスター'!$B$2:$B$60))))&CHAR(10)&"【判定ルール】"&TEXTJOIN(" ",TRUE,'原因分類ルールマスター'!$A$2:$A$60)&CHAR(10)&"【参考】大分類:"&$H2&"／中分類:"&$K2&"／発生場面:"&$Q2&CHAR(10)&"【クレーム内容】"&CHAR(10)&$F2&CHAR(10)&"【出力形式】原因名を1つだけ。")
```

**S2（AI原因分類）**
```
=AI($R2)
```

> **N,O,T,U,Y（確定列）には数式を入れません**（人がプルダウンで選択）。

## 5. AI判定用プロンプト設計

各AI関数へ渡すプロンプトは、対応する結合文セル（G/J/W/L/P/R）が生成します。共通構造：

```
役割定義 ＋ 判定方針
【候補と定義】…マスターから動的生成（表記どおりに出力させる）
【参考】…上位のAI判定結果（大→中→小→場面→原因の順に受け渡し）
【クレーム内容】…匿名化済みテキスト(F)
【出力形式】…「◯◯名を1つだけ」＝余計な説明を出させない
```

**「何でも接客・応対／その他になる」対策**：
- 大分類プロンプトに「安易に接客・応対やその他へ寄せない」を明記。
- 各大分類の「しない例」「着眼点」を候補に含め、境界を明示。
- 「お客様が最初に強く不満を持った主因／場面」で判定する方針を全段で統一。

## 6. 個人情報の匿名化（2案比較・推奨実装）

| 案 | 方法 | 長所 | 短所 |
|---|---|---|---|
| 案1 | `REGEXREPLACE` の多段ネストを数式だけで | GAS不要 | 数式が長大でネストが深く「開始括弧不足」等のエラーが出やすい。保守困難 |
| **案2（推奨）** | **GASカスタム関数 `=ANONYMIZE(E2)`** | パターンを1か所で保守。警告も同居。セルは短い | スクリプト導入が必要（本システムは元々GAS前提） |

→ **案2を実装**（`src/Anonymize.gs`）。F列は `=ANONYMIZE(E2)` だけ。

匿名化対象：メール / URL / 郵便番号 / 電話番号 / 会員・注文・レシート番号 / ラベル付き氏名（氏名：等）/ ラベル付き住所（住所：等）/ 7桁以上の数字列。

**過剰削除の防止**：氏名・住所は「ラベルの直後」だけを、**空白・句読点で必ず停止**してマスクします。
これにより商品名・店舗名・地名・クレームの意味（例：「国産牛肉が傷んでいた」）を残します。

**警告列（任意）**：`=ANONYMIZE_WARN(E2)` を空き列に置くと、ラベルなしの「◯◯様/さん」など
匿名化しきれなかった可能性を「要確認:…」と表示します。

**案1（数式版）を使いたい場合**（F2、簡易版）：
```
=IF($E2="","",REGEXREPLACE(REGEXREPLACE(REGEXREPLACE(REGEXREPLACE(REGEXREPLACE($E2,"[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}","[メール]"),"https?://[^\s、。]+","[URL]"),"0\d{1,4}[-\-]?\d{1,4}[-\-]?\d{3,4}","[電話番号]"),"(氏名|お名前|顧客名)[:：][^\s、。]{1,20}","$1：[氏名]"),"\d{7,}","[番号]"))
```
> 案1はパターン追加のたびに全行の数式修正が必要になるため、案2を推奨します。

## 7. プルダウン設定方法

確定列に「範囲を参照するデータの入力規則」を設定します（GASで自動設定されます）。手動の場合：

| 列 | データ範囲 |
|---|---|
| N 確定大分類 | `大分類一覧!A2:A12` |
| O 確定中分類 | `仕訳ルールマスター_中分類!B2:B400` |
| Y 確定小分類 | `仕訳ルールマスター_小分類!C2:C1500` |
| T 確定発生場面 | `発生場面マスター!A2:A60` |
| U 確定原因分類 | `原因分類マスター!A2:A60` |

- 「無効なデータには警告を表示」に設定（AIの表記揺れを手修正できるように）。
- **任意の依存プルダウン**：`onEdit`（`src/Code.gs`）が、N選択でO候補を、O選択でY候補を、
  その行だけ大分類・中分類で絞り込みます。失敗しても全件リストが有効なので運用は止まりません。

## 8. Google Apps Script（完成コード）

`src/` にファイル分割で収録：

| ファイル | 役割 |
|---|---|
| `src/Config.gs` | シート名・列位置・AI関数名・上限行数・**全マスターデータ**（変更してよい値を集約） |
| `src/Setup.gs` | シート作成・ヘッダ・マスター投入・**数式ビルダー**・プルダウン・精度検証構築 |
| `src/Anonymize.gs` | 匿名化カスタム関数 `ANONYMIZE` / `ANONYMIZE_WARN` |
| `src/Code.gs` | メニュー・onEdit依存プルダウン・テストデータ投入 |

**安全設計**：
- クレーム記録の **A〜E（原文）と N/O/T/U/Y（確定値）は絶対に上書きしない**。
- 上書きするのはシステム管理列の数式のみ。マスターは毎回最新化。
- **二重実行しても壊れない**（存在チェック＋数式再設定）。
- AI数式は「原文がある行だけ」に設定し、空行で `AI("")` を呼ばない（エラー・コスト対策）。
- `try/catch` とエラー時アラート、`Logger.log` でログ出力。
- 実行前に「どのシート・列を変更するか」を `SETUP_PLAN` で確認可能（メニュー「セットアップ計画を表示」）。

## 9. セットアップ手順

1. 対象のGoogleスプレッドシートを開く。
2. 拡張機能 → **Apps Script** を開く。
3. `src/` の4ファイル（`Config.gs` / `Setup.gs` / `Anonymize.gs` / `Code.gs`）を、
   同名のスクリプトファイルとして作成し中身を貼り付ける。
4. 保存 → スプレッドシートを再読み込み。メニュー **「クレームAI分類」** が出る。
5. **「① 初期セットアップ（全シート作成）」** を実行（初回は承認ダイアログを許可）。
   → 全シート・ヘッダ・マスター・数式・プルダウン・精度検証が構築される。
6. `クレーム記録` の A〜E に実データを入力（または貼り付け）。
7. **「② 数式を全データ行へ適用」** を実行。→ 入力行にF〜X（AI含む）が設定される。
8. AI関数が `Gemini` の環境では、`src/Config.gs` の
   `const AI_FUNCTION_NAME = 'AI';` を `'Gemini'` に変えて 5〜7 を再実行するだけ。

> GASを使わず数式だけで運用する場合：`masters/` のCSVを各シートに貼り付け、
> §3 の数式を各列の2行目に入れて下方向にコピーしてください。

## 10. テスト方法

メニュー「テストデータを投入（5ケース）」で仕様14の5件を投入し、AI判定を確認できます。

| ケース | 入力 | 期待 大分類 | 期待 中分類 | 期待 発生場面 |
|---|---|---|---|---|
| 1 | レジ担当者のネイルが長く衛生面が気になった | 接客・応対 | 身だしなみ不備 | レジ会計時 等 |
| 2 | 特売品が棚になく入荷予定も分からなかった | 商品管理・売場管理 | 欠品／在庫案内誤り | 欠品・在庫確認時 |
| 3 | 棚は198円だがレジで248円 | 価格・表示 | 値札違い／レジ価格違い | レジ会計時 |
| 4 | セルフレジでEdyの支払い未完了のまま退店 | システム・機器 等 | セルフレジ操作案内不足／決済端末不具合 | セルフレジ利用時 |
| 5 | 返品可と言われ後日別担当に不可と言われた | サービス・手続き | 返品交換対応不備／サービス基準不統一 | 返品・返金・交換対応時 |

- ケース1は「身だしなみ不備」に入り、商品の異物・店舗衛生とは区別されます（プロンプトで明示）。
- ケース4はマスターの境界ルール（セルフレジ=セルフレジ利用時、案内不足か端末不具合か）で一貫分類。
- ケース5の原因分類は「判断基準不統一」「ルール周知不足」が候補になります。

**AI関数が使えない環境での検証**：H/K/X 等のAIセルを一時的に手入力し、
G/I/J/V/W の結合文が正しく候補を絞り込めているか（プロンプト内容）を目視確認できます。

## 11. 想定エラーと対処

| エラー / 症状 | 原因 | 対処 |
|---|---|---|
| この関数は他の関数と併用できません | AI関数を他関数と同一式に入れた | AI列は `=AI(単一セル)` のみにする（本構成は準拠済み） |
| FILTER の範囲サイズが一致しません | 抽出範囲と条件範囲の行数不一致 | 本構成は全て同一上限行（400/1500/60）。マスター行を上限超で増やしたら `Config.gs` の `LIMITS` を増やし再セットアップ |
| 数式の開始括弧が足りないようです | 結合文の括弧不足 | §3の数式をそのまま貼る。手編集時は括弧対応を確認 |
| `#REF!` / シートが見つからない | シート名の表記揺れ | シート名は `SHEETS` 定数どおりに。リネームしない |
| AIが空欄／`Loading...`のまま | 空行でAI("")を呼んだ／API未有効 | AI数式は原文行だけに設定（②で自動）。AI機能の有効化を確認 |
| プルダウンに出ない値がある | マスター未反映 | マスター更新後に②を再実行、または範囲を確認 |
| 承認を求められる | カスタム関数/トリガの初回 | 実行時に表示される承認を許可 |
| 分類が「接客・応対」「その他」に偏る | 定義・境界が弱い | 各マスターの「しない例」「着眼点」を追記し②を再実行 |

---

## 12. AI判定精度を確認する方法（`精度検証` シート）

- **一致率**：大/中/小/発生場面/原因分類ごとに「確定済み件数・一致件数・一致率」を自動集計。
  （AI列＝確定列 かつ 確定列が入力済み の行のみを母数にする）
- **偏りチェック**：AI大分類の「接客・応対」件数・割合、「その他」件数・割合。
- **誤分類一覧**：確定済みで AI≠確定 の行を、受付No・原文・AI値・確定値付きで一覧表示（大分類・中分類）。

**改善サイクル（PDCA）**：
1. 誤分類一覧で外した傾向を把握。
2. 該当マスターの「定義／入る例／しない例／着眼点」を修正（＝AIの判定基準に即反映）。
3. 「② 数式を全データ行へ適用」で再判定 → 一致率の改善を確認。

マスターを直せばAIの判定基準に直結する構造なので、現場担当者だけでPDCAを回せます。

## 13. 置いた仮定（要確認）

- **小分類マスターはサンプル**。準備済みの大中小分類がある前提のため、`Config.gs` の `MASTER_SHO`
  （＝CSV）を差し替える運用としました。列構成（大/中/小/定義/入る例/しない例）は維持してください。
- 発生場面「マスター」＝候補＋定義、「ルールマスター」＝判定ルール文、と役割分担しました
  （原因分類も同様）。仕様の必須候補は全て収録済みです。
- 中分類の具体名（例：欠品／値札違い／セルフレジ操作案内不足 等）はテストケースを通すために
  設計した名称です。貴社の確定名称があれば中分類マスターを置き換えてください。
- AI関数は `=AI(prompt)` の単一引数形式を前提。環境が `=Gemini()` の場合は `AI_FUNCTION_NAME` を変更。
- 上限行数（中分類400／小分類1500／場面・原因60／集計1000）は現実的な既定値。増える場合は `LIMITS` で調整。
- 匿名化は数式・スクリプトのみでの完全匿名化は困難という前提のもと、過剰削除を避けた保守的設計とし、
  取りこぼしは `ANONYMIZE_WARN` で警告する方針にしました。
