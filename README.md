# クレーム（ご意見）AI自動分類システム

Googleスプレッドシートの **AI関数（`=AI()` / `=Gemini()`）** で、ご意見原文から
**大分類 → 中分類 → 小分類 → 発生場面 → 原因分類** を自動で候補出しし、人が確定する運用の一式です。

**★ご提供いただいた実際の列構成（メイン表「ご意見記録」A〜CI列）と、大中小分類ツリーに準拠**しています。
そのままコピーして使える **数式・GASコード・マスター表** を同梱しています。

---

## 0. 実データに合わせた設計方針（重要）

いただいた添付（正しい列構成・分類ツリー）に合わせ、**既存の本番シートを壊さない**ことを最優先にしました。

- メイン表 **「ご意見記録」**（87列・社員情報や管理列を含む）はそのまま使用します。
- システムが**書き込むのは下表の列だけ**。**原文AB・要約AC・確定値AK〜AO・個人情報N/O/P・社員/管理列BB〜CIには一切触れません**。
- 既存の列位置を1つもずらさないため、**小分類の補助列だけを末尾 CJ/CK/CL に新設**します。
- マスター類（分類定義）はメイン表とは別のシートで管理し、AIの判定基準として参照します。

> メイン表名が「ご意見記録」以外なら、`src/Config.gs` の `SHEETS.CLAIM` を実名に変えるだけで対応します。

### ★列の並び替えに対応（見出し名で自動検出）
スクリプトは列位置を**1行目の見出し名から毎回自動で解決**します。列を挿入・移動・並び替えしても、
**見出しテキストさえ一致していれば** ②・onEdit・プルダウン・精度検証はそのまま動きます。

- 対応表は `src/Config.gs` の `HEADER_TEXT`（キー→見出しテキスト）。**見出しを改名したら、ここも更新**してください。
- 見出しの一致は「前後空白の除去・全角/半角カッコの吸収」まで自動で行います（`内容（原文）`＝`内容(原文)` 等）。
- システム補助列（小分類候補文／小分類用結合文／要約用結合文）が無ければ**末尾に自動新設**します。
- 必須見出しが見つからない場合は、**不足している見出し名を列挙して停止**します（誤った列への書き込みを防止）。
- 見出しが全く無い新規シートでは、`COL`/`CL` の固定既定位置にフォールバックします。

## 1. メイン表「ご意見記録」の列と本システムの役割

システムが関与する列のみ抜粋（他の管理列・社員列はそのまま）。

| 列 | 項目 | システムの扱い |
|---|---|---|
| N/O/P | 氏名/電話番号/メールアドレス | **触れない**（匿名化は原文AB→ADで実施） |
| AB | 内容（原文） | **触れない**（入力元） |
| **AC** | 内容（要約） | 数式 `=AI(CL)` ← **AIが200文字・顧客目線で要約**（既存要約は上書き） |
| **AD** | AI投入用テキスト | 数式 `=ANONYMIZE(AB)`（匿名化） |
| **AE** | AI大分類 | `=AI(AP)` |
| **AF** | AI中分類 | `=AI(AR)` |
| **AG** | AI小分類 | `=AI(CK)` ← 新設CKを参照 |
| **AH** | AI発生場面 | `=AI(AT)` |
| **AI** | AI原因分類 | `=AI(AU)` |
| **AJ** | AI理由 | `=AI(AS)` |
| AK〜AO | 大/中/小/発生場面/原因（確定） | **値は触れない**・プルダウンのみ設定 |
| **AP** | 大分類用結合文 | 数式（候補＋ルール＋AD） |
| **AQ** | 中分類候補文 | 数式（AEでFILTER） |
| **AR** | 中分類用結合文 | 数式（AQ＋AE＋AD） |
| **AS** | 補助セル | 数式（AI理由用の結合文） |
| **AT** | 発生場面候補文 | 数式（候補＋ルール＋AE/AF＋AD） |
| **AU** | 原因分類候補文 | 数式（候補＋ルール＋AE/AF/AH＋AD） |
| **CJ** | 小分類候補文 ★新設 | 数式（AE×AFでFILTER） |
| **CK** | 小分類用結合文 ★新設 | 数式（CJ＋AE＋AF＋AD） |
| **CL** | 要約用結合文 ★新設 | 数式（AC=AI要約 の入力プロンプト） |

**なぜCJ/CKを末尾追加か**：AB〜AUの間に列を挿入すると社員情報・管理列（BB〜CI）を含む全参照がズレて事故になります。
末尾に足せば既存を1つも壊さず小分類パイプラインを追加できます。処理の論理順序（大→中→小）は数式内の参照で担保され、物理的な並びに依存しません。

## 2. 分類ツリー（大18 / 中31 / 小70）— 添付マスタ準拠

## 4. プルダウン設定

| 列 | データ範囲 |
|---|---|
| AK 大分類 | `大分類一覧!A2:A12` |
| AL 中分類 | `仕訳ルールマスター_中分類!B2:B200` |
| AM 小分類 | `仕訳ルールマスター_小分類!C2:C400` |
| AN 発生場面 | `発生場面マスター!A2:A60` |
| AO 原因分類 | `原因分類マスター!A2:A60` |

- 「無効なデータには警告」に設定（AIの表記揺れを手修正可能に）。
- **依存プルダウン（親子関係）**：
  - **AK（大分類）を選ぶ → AL（中分類）はその大分類に紐づく中分類だけ**に絞り込まれます。
  - **AL（中分類）を選ぶ → AM（小分類）はその中分類に紐づく小分類だけ**に絞り込まれます。
  - 仕組み：`onEdit`（`src/Code.gs`）が選択を検知し、その行のAL/AMの候補をマスターから絞り込んで再設定。
  - **既存行**も②実行時に「現在の確定値」で自動絞り込み（`narrowExistingRows_`）。onEditに頼らず反映されます。
  - 一括貼り付け等で絞り込みが反映されない時は、メニュー **「確定プルダウンを絞り込み直す（全行）」** で再適用できます。
  - 親（大分類/中分類）未選択の間は全件が選べます（選べる状態を保つため）。親を選ぶと子が絞られます。

## 5. 個人情報の匿名化（2案比較・推奨実装）

| 案 | 方法 | 長所 | 短所 |
|---|---|---|---|
| **案1（現在の既定）** | **`REGEXREPLACE` の純粋数式**（GASで自動生成） | カスタム関数に依存せず、スクリプト不具合の影響を受けない。動作が堅牢 | パターン変更時は数式の再生成（②）が必要 |
| 案2 | GASカスタム関数 `=ANONYMIZE(AB2)` | パターンを1か所で保守。警告も同居 | スクリプトに読み込みエラーがあると全列 `#ERROR!` になる弱点 |

→ **堅牢性を優先し、AD列は案1（純粋な REGEXREPLACE 数式）を既定**にしました（②で自動設定）。
案2の `ANONYMIZE`/`ANONYMIZE_WARN` は `src/Anonymize.gs` に残しており、任意で `=ANONYMIZE(AB2)` として使えます。
対象：メール/URL/郵便番号/電話番号/会員・注文・レシート番号/ラベル付き氏名・住所/7桁以上の数字列。
**過剰削除防止**：氏名・住所は「ラベル直後」だけを空白・句読点で停止してマスクし、商品名・店舗名・意味を残します。
**警告（任意）**：`=ANONYMIZE_WARN(AB2)` で、ラベルなしの「◯◯様/さん」など取りこぼしを「要確認:…」表示。

> なお本表は N=氏名・O=電話・P=メール を別列で保持しています。AIへ渡すのは匿名化後のAD列のみとし、
> N/O/P列はAIに参照させません。

## 6. Google Apps Script（完成コード）

| ファイル | 役割 |
|---|---|
| `src/Config.gs` | シート名・**実列位置(A〜CI)**・AI関数名・上限行数・**全マスターデータ** |
| `src/Setup.gs` | マスター構築・**数式ビルダー**・プルダウン・精度検証・メイン表への安全な適用 |
| `src/Anonymize.gs` | 匿名化 `ANONYMIZE` / `ANONYMIZE_WARN` |
| `src/Code.gs` | メニュー・依存プルダウン(onEdit)・テスト投入 |

**安全設計**：
- メイン表で触れるのは §1 の数式列＋AK〜AOプルダウンのみ（`FORMULA_TARGET_COLS` で定義）。
  原文AB・要約AC・確定値・PII・社員/管理列は絶対に上書きしません。
- 数式適用は**確認ダイアログ**付き（対象列を明示）。原文がある行だけにAI数式を設定（`AI("")`防止・コスト対策）。
- 二重実行しても壊れない。`try/catch`＋アラート、`Logger.log`でログ出力。メニュー「変更内容（計画）を表示」で事前確認可。

## 7. セットアップ手順

> **★推奨（最も確実）**：`dist/クレームAI分類_統合版.gs` を使うと、**1ファイル貼り付けるだけ**で済みます。
> 4ファイルを別々に貼ると不整合（`ReferenceError` 等）が起きやすいため、統合版を推奨します。
> 手順：Apps Scriptで**既存のスクリプトファイルをすべて削除 → 新規ファイルを1つ作成 → 統合版の中身を全部貼り付け → 保存**。

1. 対象スプレッドシートで 拡張機能 → **Apps Script** を開く。
2. （推奨）`dist/クレームAI分類_統合版.gs` を1ファイルに貼り付け。または `src/` の4ファイルを同名で作成し貼り付け → 保存 → シート再読み込み。メニュー「クレームAI分類」が出る。
3. **「① マスター系シートを作成/更新」** を実行（初回は承認）。→ 分類マスター・大分類一覧・設定・精度検証を構築。
4. `Config.gs` の `SHEETS.CLAIM` が実際のメイン表名（例：`ご意見記録`）と一致しているか確認。
5. **「② メイン表に数式・プルダウンを適用」** を実行 → 確認ダイアログでOK。
   → 補助列(AD/AP/AQ/AR/AS/AT/AU/CJ/CK)はテンプレとして空行にも設定、AK〜AOにプルダウンが付く。
   → **AI列(AE〜AJ)は AB(原文)にデータがある行だけ**に設定されます（空行で `AI("")` を呼ばないため）。
   → よって **AB列に原文が1件も無いとAI列は入りません**。原文を入れてから②を再実行してください。
   （テンプレ行数は `Config.gs` の `LIMITS.TEMPLATE_ROWS` で調整可）
6. AI関数が `Gemini` の環境では `AI_FUNCTION_NAME='Gemini'` に変えて ①②を再実行。

> GASを使わず数式だけで運用する場合：`masters/` のCSVを各シートに貼り付け、§3 の数式を各列の2行目に入れて下方向コピー、
> §4 のプルダウンを手動設定してください（CJ/CK/CL 列は手動で追加）。

## 7.5 日常の運用方法（毎回スクリプトを実行しなくてOK）

初期セットアップ（①②）は最初の1回だけです。日常運用では **AB列（原文）に入力するだけ** で自動分類されます。

**仕組み**：`onEdit` トリガが、AB列への入力/貼り付けを検知し、**その行に自動で全数式を反映**します（AC要約・AD匿名化・AE〜AJのAI分類まで）。

| 運用シーン | やること |
|---|---|
| **1件ずつ受付入力** | AB列に原文を入力するだけ → その行が自動で分類される（②不要） |
| **複数件をまとめて貼り付け** | AB列に複数行を貼り付け → 貼り付けた各行が自動反映（件数が多い時は下記②推奨） |
| **CSV等で大量インポート** | インポート後に一度だけ **②** を実行（onEditはインポートで発火しないため） |
| **分類マスターを直したとき** | ①でマスター更新 → 精度改善。既存行は再判定させたければ②を実行 |
| **人による確定** | AK〜AOのプルダウンで確定（AI結果とは別に保持。精度検証で突合） |

**まとめ**：
- **通常は「AB入力だけ」**。スクリプト実行は不要。
- **②を使うのは**：初回セットアップ／大量インポート後／全行の数式を一括で貼り直したいとき、の3場面だけ。
- onEditは簡易トリガのため権限設定不要。もし自動反映が動かない環境でも、②を押せば同じ結果になります。

> 補足：AI列は原文がある行だけに入る設計は維持しています（空行で `AI("")` を呼ばないため）。
> onEditは「原文が入った行」に対してだけ数式を入れるので、無駄なAI呼び出しは発生しません。

## 7.6 分類（大・中・小／発生場面／原因分類）の追加・変更方法

分類は**マスターシートを直接編集**するのが基本です。マスターを直すと、AIの判定基準（プロンプトに注入）と
プルダウンの両方に反映されます。**①「マスター作成/更新」は既存の分類を上書きしません**（手編集は温存されます）。

### 追加する場所（1シートだけ編集すればOK）

| 追加したいもの | 編集するシート | 追加する行の内容 |
|---|---|---|
| **大分類** | `仕訳ルールマスター_大分類` | 大分類／定義／入る例／しない例／着眼点 |
| **中分類** | `仕訳ルールマスター_中分類` | 大分類／中分類／定義／入る例／しない例 |
| **小分類** | `仕訳ルールマスター_小分類` | 大分類／中分類／小分類／定義／入る例／しない例 |
| **発生場面** | `発生場面マスター` | 分類名／定義／入る例／しない例 |
| **原因分類** | `原因分類マスター` | 分類名／定義／入る例／しない例 |

- **親子関係は「大分類・中分類の列」で決まります**。小分類を足すときは、その行の大分類・中分類を
  既存の名称と**完全一致**で書いてください（例：大分類「レジ接客」＋中分類「接客態度」の行に小分類を追加）。
- 追加後、**新しい行**は次にAB(原文)を入力した時点で候補・プルダウンに反映されます。
- 既存行のAI結果も、結合文がマスターを参照しているため**自動で再判定**されます
  （マスター定義を直すと既存行のAI列が計算し直されます。件数が多いと再計算に時間がかかります）。

### 変更（定義の見直し／改名）

- **定義・入る例・しない例の修正** … そのまま書き換えるだけ。次回計算からAI判定に反映（PDCAの中心）。
- **分類名の改名** … マスターの名称を変えると、AIは新名称で出力しますが、
  既に人が確定した値（AK〜AO）や過去のAI出力は旧名称のまま残ります。改名時は
  「新名称を追加 → 旧名称の行を段階的に置換」する運用が安全です。

### 注意点

- **上限行数**：大分類は30、中分類200、小分類400、発生場面/原因60まで（`Config.gs` の `LIMITS`）。
  これを超えて増やす場合だけ、`LIMITS` の数値を増やして **②を再実行**してください。
- **確定プルダウン**は編集後すぐ反映されます（大分類は `仕訳ルールマスター_大分類` を直接参照）。
- **既定値へ戻したいとき**だけ、メニュー「**マスターを既定値で再作成（上書き注意）**」を使います
  （手編集はすべて破棄されるので確認ダイアログ付き）。
- CSV（`masters/`）から貼り直す場合も、貼り付け後は上記と同じく即反映されます。

**まとめ**：分類の追加・変更は **マスターシートを直接編集するだけ**。①は上書きしないので安全、
既定に戻す時だけ専用メニューを使う、という運用です。

## 7.7 店番から店舗情報を自動補完（店舗マスタ連携）

受付表の **「店番」に4桁の店番を入力すると、店名・営業統括部・営業部・ブロック・エリアが自動で"値"として入ります**（記録として凍結。後日マスターが変わっても過去記録は当時のまま）。

- **前提**：同じスプレッドシート内に **「店舗マスタ」シート**があり、見出しに `店番／店名／営業統括部／営業部／ブロック／エリア` が存在すること（列の並びは自由。見出し名で照合）。
- **受付表側**：見出し `店番／店名／営業統括部／営業部／ブロック／エリア` の列に書き込みます（並び順不問）。
- **動作**：`店番` を入力/変更すると `onEdit` がその行を補完。空欄やマスタに無い店番の行は既存値のまま（触れません）。
- **一括補完**：CSV等で大量に取り込んだ後は、メニュー **「店番から店舗情報を一括補完（全行）」** で全行まとめて補完できます。
- **先頭ゼロ対策**：`123` と `0123`、数値/文字のどちらでも一致するよう **4桁ゼロ埋めで正規化**して照合します。
- 「店舗マスタ」シートは**ユーザー管理**で、システムは読むだけ（作成・上書きしません）。設定は `Config.gs` の
  `SHEETS.STORE` / `STORE_KEY_HEADER` / `STORE_FILL_HEADERS`。補完する項目を増減したい場合は `STORE_FILL_HEADERS` を編集。

## 8. テスト方法（メニュー「テストデータを投入（5ケース）」）

メイン表末尾にA列=「TEST」の目印付きで5件を投入し数式を適用します（テスト行は後で削除可）。

| ケース | ご意見 | 期待 大分類 | 期待 中分類 | 期待 小分類 |
|---|---|---|---|---|
| 1 | レジ担当者のネイルが長く衛生面が気になった | レジ接客 | 接客態度 | 身だしなみ |
| 2 | チラシ特売品が棚になく入荷予定も不明 | 欠品・特注 | 欠品 | チラシ |
| 3 | 棚は198円だがレジで248円 | アンマッチ | 売価アンマッチ | 売価アンマッチ |
| 4 | 売場で在庫を聞いたが調べてくれなかった | 外周り接客 | 売場・作業時 | 在庫確認・問い合わせ対応 |
| 5 | 返品可と言われ後日別担当に不可と言われた | 外周り接客 | 売場・作業時 | 返品・交換対応 |

- ケース1は「接客態度／身だしなみ」に入り、店舗の清掃衛生（クリンリネス）とは区別されます（プロンプトで明示）。
- 依存FILTERにより、大分類が決まると中分類候補が、中分類が決まると小分類候補が限定され、ツリー外の値は出ません。
- AI関数が使えない環境では、AE/AF/AG を一時的に手入力し、AQ/CJ/CK 等の候補文が正しく絞れているか目視確認できます。

## 9. 想定エラーと対処

| 症状 | 原因 | 対処 |
|---|---|---|
| この関数は他の関数と併用できません | AI関数を他関数と同一式に | AI列は `=AI(単一セル)` のみ（本構成準拠） |
| FILTER の範囲サイズが一致しません | 抽出範囲と条件範囲の行数不一致 | 全て同一上限行（中200/小400/60）。マスターを上限超で増やしたら `Config.gs` の `LIMITS` を増やし再適用 |
| 数式の開始括弧が足りないようです | 結合文の括弧不足 | §3の数式をそのまま貼る |
| `#REF!`/シートが見つからない | シート名の表記揺れ／メイン表名不一致 | `SHEETS` 定数どおりに。`SHEETS.CLAIM` を実名に合わせる |
| AIが空欄のまま | 原文が無い行でAI呼び出し／AI未有効 | AI数式は原文行だけ（②で自動）。AI機能の有効化を確認 |
| メイン表が見つからない | シート名が「ご意見記録」でない | `SHEETS.CLAIM` を変更 |
| 分類が「その他」に偏る | 定義・境界が弱い | 各マスターの「しない例」「着眼点」を追記し②を再実行 |

## 10. AI判定精度を確認する方法（`精度検証` シート）

- **一致率**：大/中/小/発生場面/原因分類ごとに「確定済み件数・一致件数・一致率」を自動集計
  （AI列＝確定列 かつ 確定列が入力済み の行のみ母数）。
- **偏りチェック**：AI大分類の「レジ接客」「外周り接客」「その他」の件数・割合。
- **誤分類一覧**：確定済みで AI≠確定 の行を、店名・内容(要約)・AI値・確定値付きで一覧（大分類・中分類）。

**改善サイクル（PDCA）**：誤分類の傾向把握 → 該当マスターの定義/入る例/しない例を修正（＝AI判定基準に即反映）→ ②再実行で再判定 → 一致率改善を確認。マスターを直せばAIの判定基準に直結します。

## 12. 置いた仮定（要確認）
